# Дорожная карта

Цель: одно приложение под Windows 10/11, которое умеет прошивать полётные контроллеры (STM32),
модули управления (ESP32) и Walksnail (Caddx Ascent), распространяется архивом со всеми
зависимостями внутри и не требует установки PowerShell, Python и других сред.

Порядок этапов выбран так, чтобы не потерять работающий функционал: legacy-скрипты остаются
рабочим инструментом, пока Rust-версия не догонит их по возможностям.

## Этап 3. Walksnail (Caddx Ascent)

Приоритет: своего решения нет, прошивать нужно сейчас.

- Статический разбор пяти версий Caddx PC Tool (dnSpy, вне репозитория), сравнение по версиям,
  выяснение причины неработоспособности v2.2.9.
- Перехват USB-трафика (USBPcap) на реальном передатчике по сценариям: 16_5_9 → 17_5_8,
  17_5_8 → 18_21_10, 18_21_10 → 19_2_14, попытка подключения в v2.2.9.
- Описание протокола в `docs/protocols/walksnail-ar.md`: кадры, команды, статусы, формат `.img`.
- Крейт `walksnail`: кодек кадров, разбор `.img`, сценарий обновления, юнит-тесты на записанных кадрах.
- Первый запуск на устройстве: только чтение информации, затем прошивка с подтверждением.
- Далее по необходимости: приёмники, частотная конфигурация, CamHub, RC-режим.

## Этап 4. Модули управления (ExpressLRS / ZLRS)

- Разбор `src/python` из репозитория ExpressLRS и образцов ZLRS (конфиг в конце образа, шифрованные
  варианты).
- Способы прошивки: UART (ESP ROM), passthrough через Betaflight (MSP), Wi-Fi (HTTP upload),
  позже EdgeTX passthrough.
- Основа — библиотека `espflash`; внешний `esptool.exe` только если нужного профиля нет в библиотеке.
- Сравнить два варианта Orange и TLRS с официальным ExpressLRS. Проверять совместимость
  по конкретной плате, версии образа и способу загрузки, а не только по имени файла.
- Замена заглушки пункта 2 меню.

## Этап 5. Полётные контроллеры

- Разбор TProgrammerCLI (Delphi, встроенный 7z-архив): определение чипа, размер дампа, MSP-переход в DFU.
- Перенос логики в Rust: CubeCLT как внешний инструмент, автоопределение чипа, автобэкап перед
  записью, выход из DFU после записи, распознавание прошивки по дампу.
- Сравнить официальные Betaflight и INAV по версиям. В отдельном CLI разделить MSP для
  определения устройства и запроса входа в DFU, USB DFU для работы с загрузчиком и текстовый
  CLI полётника для `dump` и параметров. Начать с чтения, перед изменениями делать бэкап
  и проверять совместимость дампа с прошивкой и платой.
- Изучить Zadig 2.9 и исходники libwdi: когда нужна привязка WinUSB, какое устройство или
  интерфейс меняется и как восстановить прежнюю привязку. Не заменять драйвер рабочего
  COM-интерфейса автоматически.
- Оценить собственный DFU-клиент на `rusb` как альтернативу CubeCLT и ImpulseRC Driver Fixer.

## Этап 6. Linux

- Сборка под Linux, udev-правила для Walksnail (CDC-ACM), ESP (CP210x/CH340) и STM32 DFU,
  обход ModemManager и brltty.
- Проверка на реальной машине. Windows остаётся основной платформой; Linux не должен усложнять
  сборку под Windows.

## Правила, которых придерживаемся

- Опасные операции (стирание, запись, даунгрейд) требуют явного подтверждения и, где возможно,
  предварительного бэкапа.
- Прошивка начинается с чтения информации об устройстве; несовпадение модели или версии — отказ.
- Код сторонних программ не копируется: в репозитории только собственные реализации и описания
  протоколов.
- Тесты не требуют подключённого оборудования.
